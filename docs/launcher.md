# Лаунчер Карантина

Лаунчер устанавливается один раз. Его Electron-оболочка, экран запуска и настройки остаются на компьютере, а версии самой игры хранятся отдельно в пользовательской папке `game-updates`.

## Работа игроков

Скачайте установщик из [постоянного выпуска лаунчера](https://github.com/nevermoreeQqq/Qurantine/releases/tag/launcher-v1.0.0). На Windows это **Quarantine-Launcher-Setup.exe**. Если уже установлена старая оболочка с полем адреса хозяина, полностью закройте игру и установите новый лаунчер в прежнюю папку. На Mac замените приложение из DMG своей архитектуры. Обновление самой игры не меняет файлы `desktop/`, поэтому оформление лаунчера обновляется именно установщиком.

- **Играть** запускает активную версию, включая кооператив до четырёх игроков.
- **Обновить игру** скачивает пакет из GitHub Releases, проверяет SHA-256, устанавливает его и перезапускает приложение.
- **Версии игры** показывает установленные версии и доступные пакеты. Сохранённые версии можно выбирать без повторного скачивания.
- Сервер хозяина, Radmin IP и папка «Загрузки» больше не нужны как источник новых выпусков в приложении. Подключение к кооперативу остаётся частью самой игры.
- Без интернета можно запускать установленную игру. Недоступность GitHub не блокирует кнопку запуска.
- У всех участников кооператива должна быть одинаковая версия игры.

Источник зафиксирован в `desktop/github-releases.cjs`: `nevermoreeQqq/Qurantine`. Адрес обновлений вводить не нужно. Доступ к закрытому репозиторию пока отложен по просьбе пользователя: готовая сборка использует публичный GitHub API и показывает понятное сообщение, если репозиторий недоступен. Токены в установщик не включаются. Разработчик может временно передать собственный токен через переменную окружения `QUARANTINE_GITHUB_TOKEN`.

## Настройки

Лимит памяти игрового окна: 512 МБ, 1, 2, 4 или 8 ГБ, с ограничением по памяти компьютера. Это параметр V8 `max-old-space-size`, применяемый при следующем запуске приложения, а не резервирование всей оперативной памяти. Общая память приложения включает графику, Electron и сервер и может быть выше.

Музыка лаунчера и её громкость меняются сразу. Настройки музыки игры, её громкости и звуковых эффектов передаются при следующем запуске игры. Они сохраняются в `launcher-settings.json` в пользовательской папке приложения. Звук лаунчера прекращается при переходе в игру.

«Сигнал периметра» — оригинальная процедурная композиция в стиле dark ambient, 84 BPM, ре минор. Для воспроизведения не нужны интернет и сторонние музыкальные файлы.

## Новые выпуски игры

После объединения ветки в `main`:

1. Обновите `version` в `package.json` и `package-lock.json`. Значение `VERSION` в `content.js` меняется только при изменении сетевого протокола.
2. Выполните `npm test` и `npm run pack:game`.
3. Создайте тег, совпадающий с версией пакета, например `v6.0.2`, и отправьте его на GitHub.
4. Workflow **Publish game version** проверит игру и загрузит в Release только `Quarantine-Game-6.0.2.qtg` и его контрольную сумму. Для этого не нужен секретный ключ подписи.
5. Отредактируйте описание Release: этот текст появится в разделе новостей лаунчера.

Каталог учитывает опубликованные стабильные Releases с готовыми пакетами игры. Черновики, предварительные выпуски и установщики не предлагаются как обновления. Проверки кэшируются на пять минут; ручная кнопка позволяет проверить раньше.

Новый формат `.qtg` содержит игровые файлы и разрешённые ресурсы из `assets/` и `web/`. Файлы `desktop/`, ключи и произвольные пути не принимаются. Доверенная SHA-256 берётся из метаданных GitHub Release Asset по HTTPS, а не из самого пакета. Сохранённый пакет проверяется повторно при запуске. Старые подписанные `.qtu` продолжают работать.

## Один выпуск лаунчера

Workflow **Publish permanent launcher** запускается вручную из `main` и собирает Windows и оба варианта macOS. После проверок всех платформ он загружает установщики и `SHA256-launcher.txt`, затем публикует один Release `launcher-v1.0.0` с постоянными именами файлов:

- `Quarantine-Launcher-Setup.exe`
- `Quarantine-Launcher-macOS-x64.dmg`
- `Quarantine-Launcher-macOS-arm64.dmg`

Обычные теги игры этот workflow не запускают. Существующие проверки Windows/macOS в pull request сохранены.

Для публикации откройте GitHub Actions → **Publish permanent launcher** → **Run workflow**, выберите `main`. Описание выпуска берётся из `docs/launcher-release-notes.md`. Первый выпуск остаётся черновиком до загрузки всех установщиков, повторный запуск обновляет файлы на той же странице.

Локальная сборка Windows: `npm run build:launcher:win`. Проверка готового приложения: `node tools/verify-windows.cjs`.

## Выпуск игры вместе с лаунчером

Для обновления оболочки лаунчера выпуск 6.0.6 включает также полные установщики. Workflow **Publish game with launcher** запускается вручную из `main`, берёт версию из `package.json`, собирает и проверяет Windows, Mac Intel и Mac Apple Silicon, пакет `.qtg` и веб-архив. После проверок он создаёт Release `v6.0.6` с описанием из `CHANGELOG-6.0.6.md`, загружает все файлы и контрольные суммы, затем публикует выпуск. Существующий Release не перезаписывается.

Это отдельный ручной выпуск приложения. Обычная публикация следующих версий игры по тегам и постоянная страница лаунчера сохраняются.

## Новости и видео

Встроенное девятисекундное видео о коллизиях 6.0.1 записано из настоящей `Simulation` с игровыми спрайтами. Его можно воспроизвести командой `npm run news:video`. Для записи нужен Electron.

В будущие Releases можно добавлять короткие ролики без изменения лаунчера: сохраните WebM в `news/6.0.2.webm` перед созданием тега или загрузите в Release файл `Quarantine-News-6.0.2.webm`. Максимум — 20 МБ. Лаунчер обнаружит его рядом с описанием обновления, проверит контрольную сумму и сохранит локально для просмотра. Произвольные ссылки в тексте новости не открываются.

Графика, новые зоны и оружие отмечены как направления будущих улучшений, без обещания сроков.

## Проверки

- `npm test`: GitHub-каталог, загрузка, контрольные суммы, установка, откат, восстановление файлов, офлайн-запуск и настройки, а также все игровые тесты.
- `npm run desktop:smoke`: запуск лаунчера и игры в Electron.
- `npx electron tools/verify-launcher-ui.cjs`: вкладки, настройки, видео и передача звука в игру. Скриншоты и отчёт сохраняются в `diagnostics/launcher/`. Используется отдельная тестовая папка; настройки пользователя не меняются.

Работа над лаунчером не меняет `game.js`, `style.css`, `index.html`, `simulation.js` и другие игровые модули, которыми может параллельно заниматься другой разработчик.
