# VPS для кооператива

Сервер рассчитан на Ubuntu 24.04 x86_64. Нужны права root при установке и входящий TCP-порт 80. Для первоначальных тестов на 1 vCPU / 1 ГБ устанавливается лимит одной комнаты, до четырёх игроков. Вместимость повышают после проверки поздних волн на самом VPS.

В распакованной копии этой ветки:

```bash
bash tools/install-vps.sh http://PUBLIC_IP 1
```

Установщик загружает Node.js 24 LTS с официального сайта и сверяет SHA-256, устанавливает только серверные зависимости, запускает игру от пользователя `quarantine` через systemd и настраивает Nginx с WebSocket на порту 80. Игра слушает только `127.0.0.1:5173`. Electron на VPS не устанавливается. Файлы приложения находятся в `/opt/quarantine/app`, настройки — `/etc/systemd/system/quarantine.service`.

В браузере Windows или macOS откройте публичный адрес. Один игрок создаёт комнату на четверых и сообщает её код. Остальные заходят по тому же адресу и коду. Radmin и включённый компьютер хозяина не требуются.

Если через VPN страница обрывает соединение, а через обычное подключение работает, добавьте публичный IP сервера в исключения VPN или отключите VPN на время игры. Не меняйте настройки SSH и брандмауэра из-за ошибки, которая возникает только через VPN.

В исправленной сборке 6.0.6 общий VPS выбран автоматически: создатель выбирает число игроков, нажимает «Создать кооп» и передаёт код. Друг вводит только код. Старые сохранённые адреса Radmin не подменяют новый сервер. Поле адреса доступно в раскрывающемся разделе «Другой сервер» для собственных локальных сетей.

Для уже установленного приложения нужна однократная установка исправленной сборки: дополнительные установщики `Quarantine-Coop-Setup-6.0.6.exe`, `Quarantine-Coop-6.0.6-macOS-x64.dmg` или `Quarantine-Coop-6.0.6-macOS-arm64.dmg` в релизе 6.0.6. Исходные установщики и тег релиза сохраняются. Автоматическое обновление по номеру версии не заменяет уже установленную 6.0.6 той же версией. В браузере версия обновляется на VPS.

Проверка и управление:

```bash
systemctl status quarantine --no-pager
journalctl -u quarantine -n 50 --no-pager
systemctl restart quarantine
curl http://127.0.0.1/api/info
```

`QUARANTINE_PUBLIC_URL` задаёт адрес, который показывается игрокам; `QUARANTINE_ROOM_LIMIT` — число одновременно созданных комнат (1–30). После изменения unit-файла выполняют `systemctl daemon-reload` и `systemctl restart quarantine`. Комнаты и матч хранятся в памяти: при перезапуске активные матчи заканчиваются.

Для встраивания в Яндекс Игры впоследствии нужны домен, HTTPS/WSS, разрешённые источники запросов и настройки CSP. Текущий HTTP-адрес предназначен для прямого тестирования в браузере и приложениях.
